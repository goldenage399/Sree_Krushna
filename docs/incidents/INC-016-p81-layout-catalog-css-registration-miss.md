# Incident Report: INC-016 — P81 Layout Catalog CSS Registration Miss

**Date**: 2026-06-20
**Status**: RESOLVED
**ID**: INC-016
**Track**: Governance / Preflight Gate
**Resolved By**: Added `#cockpit-update-form` CSS rule to `modals-overlays.css`; rebuilt layout catalog. Commit `b3a61793`.  
**Keywords**: layout-catalog, css-registration, id-selector, P81, preflight-gate, modals-overlays, layout-catalog-json
**Topology Layer**: Component Authority
**Ownership Type**: css-registration
**Symptom Tags**: p81-gate-block, id-selector-miss, catalog-miss

---

## 1. Executive Summary

During the EUR-002 visual parity pass (commit `b0dfe62d`), a new JSX form element with `id="cockpit-update-form"` was added to `TaskUpdateModal.jsx`. No corresponding CSS selector rule was added to any stylesheet. The P81 preflight gate correctly detected the miss and blocked the next commit (`b3a61793`). The resolution required adding a `#cockpit-update-form { display: block; }` rule to `src/styles/components/modals-overlays.css` and rebuilding `dist/layout-catalog.json`.

The P81 gate functioned as designed. The gap is a process one: the agent executing the parity pass did not know that adding an HTML `id=` attribute to a JSX layout container requires a corresponding CSS rule to satisfy the layout catalog gate.

---

## 2. Architectural Surface Mapping (6-Surface Audit)

### 1. UI Surface

**Impact**: ✅ AFFECTED.
`id="cockpit-update-form"` added to the `<form>` element inside `TaskUpdateModal.jsx` cockpit variant (line 492). No CSS rule existed for the selector, so the layout catalog did not index it. No visual regression — the form renders correctly. The catalog miss is a governance artifact only.

**Correction**: Added `#cockpit-update-form { display: block; }` to `src/styles/components/modals-overlays.css`. Catalog rebuilt via `npm run cache:build:layout`. 336 selectors now indexed.

### 2. Data Surface

**Impact**: ✅ NOT AFFECTED.
No schema, Firestore, or write-path changes involved. The `id` is a DOM attribute for the associated `<button form="cockpit-update-form">` pattern — no data layer interaction.

**Justification**: The `cockpit-update-form` id is exclusively a DOM relationship handle between the form and its submit button. No data is written to or read from this attribute.

### 3. Reactive Surface

**Impact**: ✅ NOT AFFECTED.
No React state, context, hook, or event handler depends on the `id` attribute. The form submission is wired via `onSubmit={handleSubmit}`, not via id-based DOM selection.

**Justification**: React does not use HTML `id` attributes for internal event delegation. The id is a native browser affordance for `<button form="...">` association.

### 4. Service Surface

**Impact**: ✅ NOT AFFECTED.
No Cloud Functions, API calls, or service layer is involved. The layout catalog is a client-side build artifact.

**Justification**: `dist/layout-catalog.json` is generated by `scripts/build-layout-catalog.cjs` from CSS files. It is not a runtime service.

### 5. Module Surface

**Impact**: ✅ NOT AFFECTED.
No package dependencies, route registrations, or file structure changes required. The fix is a single CSS rule addition to an existing file.

**Justification**: `modals-overlays.css` is already imported and processed by the build. No new module imports were needed.

### 6. Governance Surface

**Impact**: ✅ AFFECTED.
P81 gate blocked the subsequent commit (`b3a61793`) because `#cockpit-update-form` appeared in the diff of `TaskUpdateModal.jsx` but was not indexed in `dist/layout-catalog.json`. The gate correctly identified the miss. The process gap: agents (and developers) adding new `id=` attributes to JSX layout containers must simultaneously add a CSS layout rule and rebuild the catalog in the same change set.

**Correction**: This INC-016 is written to institutionalize the rule. See Phase 3.

## 3. Root Cause

The parity pass (commit `b0dfe62d`) added `id="cockpit-update-form"` for the `<button form="...">` affordance. The agent executing the parity pass was not aware that the P81 gate requires a corresponding CSS selector entry in `dist/layout-catalog.json`. The catalog is built from CSS files; `id=` attributes in JSX are not automatically registered.

**Cause classification**: Intentional feature addition with forgotten CSS registration step.

---

## 4. Invariant Classification (Phase 2)

**Is this a new structural invariant?** No — P81 already exists as a gate. The invariant is: *every layout container `id` added to JSX must have a corresponding CSS rule registered in the layout catalog*.

**Is this a process pattern gap?** **Yes.** The existing P81 gate catches the violation, but no documentation or checklist reminded the agent to add the CSS rule at the time the `id` was written. The corrective process (add CSS rule → rebuild catalog) must be captured in agent-readable form.

**ADR Gap Check**: No ADR covers the layout catalog registration step. The P81 gate's PREFLIGHT.md row R13 says "run `npm run cache:build:layout`" but does not explain *when* this must be done (i.e., at the point of adding an `id=` attribute, not after the commit fails).

## 5. Process Pattern (Phase 3 — `.agent/patterns/`)

**Pattern to capture**: "When adding `id=` to a JSX layout container, add CSS rule + rebuild catalog in same changeset."

This is a **process/methodology pattern** (not a pure code invariant) → capture in `.agent/patterns/`.

See: `.agent/patterns/p81-id-registration-process.md` (created as part of this governance run).

## 6. PREFLIGHT.md Coverage Audit

The existing PREFLIGHT.md row R13 (P81) instructs to run `npm run cache:build:layout` when the gate fails. The gap is that it does not say *proactively rebuild when adding `id=` to a JSX component*. The R13 description should be updated to include a trigger condition.

## 7. Litmus Test

> *"If a new developer adds `id="my-form"` to a JSX component tomorrow, is it architecturally impossible for them to commit without satisfying P81?"*

**No** — P81 catches it at commit time. The gate works. What's missing is the forward-looking guidance: "before you commit after adding an `id=`, run `npm run cache:build:layout` and add the CSS rule."

> *"Is there an ADR that would have made this architecturally impossible to introduce?"*

No ADR required — P81 already enforces. The gap is in process documentation, now addressed by INC-016 and the captured pattern.
