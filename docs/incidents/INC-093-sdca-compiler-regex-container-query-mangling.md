# INC-093 — SDCA Build Compiler Regex At-Rule Container Query Mangling

**Incident ID**: `INC-093`  
**Date**: `2026-09-18`  
**Severity**: Medium (Build Integrity & Responsive CSS Container Query Parsing)  
**Status**: RESOLVED & INSTITUTIONALIZED  
**Reporter / Primary Investigator**: Antigravity Agent & UI Council  
**Governing Standard**: `STD-MOD-COMP-001`, `INV-SDCA-004`, `sdca-container-query-scoping.md`  
**Affected Components**: `cockpit_src/build.cjs`, `shopping_src/build.cjs`, `decision_registry_src/build.cjs`, `scripts/verify-modular-architecture.cjs`  
**Related Patterns**: `.agent/patterns/sdca-container-query-scoping.md`, `.agent/patterns/monolithic-engine-port-css-scoping-gate.md`  

---

## Architectural Surface Mapping

1. **UI Surface**: Responsive `@container` breakpoints in Decorator Cockpit (`02_hud.css`), Shopping Registry, and Decision Registry were rendered inactive on narrow screens, falling back to desktop layout widths because the container query was ignored by the browser CSS parser.
2. **Data Surface**: Non-breaking for Firestore schema or tabular records, but data presentations within containerized cards failed to adapt column widths and spacing on viewports $<680\text{px}$.
3. **Reactive Surface**: The client-side state machine operated properly, but the DOM visual containers failed to reflow when container dimensions mutated dynamically.
4. **Service Surface**: No cloud service impact; offline and hosted runtime environments were identically affected by the mangled stylesheet emitted during local assembly.
5. **Module Surface**: The SDCA CSS scoping compiler (`build.cjs` across all `*_src` modules) contained an incomplete regex parser that treated `@container` as an ordinary CSS selector rather than a root at-rule block.
6. **Governance Surface**: Missing guardrail in `scripts/verify-modular-architecture.cjs` to verify that at-rule regex parsing covers all CSS nested at-rules (`@(media|container|supports|layer)`).

---

## 1. Executive Summary & Symptom

During the multi-viewport responsive reflow enhancement (SK-005), CSS container queries (`@container (max-width: 680px) { ... }`) were added to `cockpit_src/styles/02_hud.css` and `shopping_src/styles/` to allow HUD metrics and shopping option pods to adapt dynamically to their parent element widths.

When running `node cockpit_src/build.cjs --fragment` and inspecting the generated `cockpit-fragment.html`, the container queries failed to trigger in browser devtools. Examination of the generated CSS revealed:
```css
/* INVALID CSS GENERATED BY NAIVE COMPILER */
#tab-cockpit #cockpitFrame @container (max-width: 680px) {
  .cockpit-hud { flex-direction: column; }
}
```
The browser's CSS engine discarded the entire block as invalid selector syntax.

---

## 2. Root Cause Analysis & Diagnostic Steps

### Step 1: Root Cause Discovery
The CSS pre-scoping function `scopeCssBlock(css, prefix)` used in all SDCA build compilers contained:
```javascript
// DEFECTIVE PARSER (Pre-INC-093)
if (css.slice(i).match(/^@media[^{]*\{/)) {
  const match = css.slice(i).match(/^(@media[^{]*\{)/);
  const mediaHeader = match[1];
  ...
}
```
Because the parser strictly tested for `@media`, it skipped this branch when encountering `@container`. The parser then reached the default selector scoping branch:
```javascript
// Treated @container as a selector, prepending prefix!
result += selectors.map(s => `${prefix} ${s}`).join(', ') + ' {\n';
```
This produced `#tab-cockpit #cockpitFrame @container (...) { ... }`.

### Step 2: Escape Analysis
- **Why did standard build exit with code 0?**
  SDCA compilers execute `node -c` for JavaScript syntax validation (`INV-SDCA-003`). However, CSS string concatenation is not parsed by a full AST linter prior to emission, allowing invalid CSS selectors to pass through build steps undetected.
- **Why did desktop testing miss it?**
  Desktop viewports ($>1024\text{px}$) rely on the default container sizing; container queries only activate when the viewport or container narrows below $680\text{px}$.

---

## 3. Preventive Guardrails & Permanent Resolution

1. **Universal At-Rule Regex (`INV-SDCA-004`)**:
   Upgraded `scopeCssBlock` across all SDCA compilers (`cockpit_src/build.cjs`, `shopping_src/build.cjs`, `decision_registry_src/build.cjs`) to use:
   ```javascript
   if (css.slice(i).match(/^@(media|container|supports|layer)[^{]*\{/)) {
     const match = css.slice(i).match(/^(@(media|container|supports|layer)[^{]*\{)/);
     const atRuleHeader = match[1];
     result += atRuleHeader + '\n';
     i += atRuleHeader.length;
     // Recurse inner rules cleanly
   }
   ```
2. **Standardized Pattern Registration**:
   Formally captured `.agent/patterns/sdca-container-query-scoping.md` with a `guarded` activation tier wired to `npm run verify:modular-architecture`.
3. **Dual-Release Compilation & Parity Check**:
   Rebuilt and verified all root and public distribution pairs with 100% byte parity.
